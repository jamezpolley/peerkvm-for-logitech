キーひとつで、全部ついてくる。

キーボードのホスト選択キーを押すだけで、マウス、クリップボード、モニター入力を同じLinuxホストへ。中央サーバーのない、暗号化されたFlowスタイルKVMです。

できること

各PCで同じ flow-node を動かします。リーダー機器が接続されたノードを、ほかのノードが認証済みLANブロードキャストで知り、手元に残っているフォロワー機器を切り替えます。

01 / DEVICES

機器を追従

キーボードをリーダーに、マウスなどをフォロワーに設定。Unifying/BoltレシーバーとBluetoothを検出します。

02 / CLIPBOARD

コピーも追従

切り替え時にクリップボードを同期。不要なノードでは設定画面から無効化できます。

03 / DISPLAY

画面入力も追従

ddcutil とDDC/CI対応モニターを使い、指定した入力へ自動切り替えします。

切り替えの流れ

例：ホスト1にあるキーボードの「2」を押した場合。

1ホスト1でキーボードが切断
2ホスト2が接続を動的検出
3ホスト2が認証済み通知を送信
4ホスト1がマウスを2へ切替
5画面入力とクリップボードを同期

インストール

すべてのLinuxホストで実施します。Python 3.10以降、IPv4ブロードキャストが通る同一LAN、同じ共有シークレットが必要です。

1

リポジトリから起動

git clone https://github.com/coddingtonbear/logitech-flow-kvm.git
cd logitech-flow-kvm
uv run --frozen logitech-flow-kvm flow-node --secret '長くランダムな共通値'
2

Bluetooth利用時の権限

同梱のudevルールを入れ、機器を再接続します。

sudo install -m 0644 rules.d/42-logitech-flow-kvm.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
3

モニター切り替え（任意）

ddcutil を導入し、モニター側でDDC/CIを有効化。実行ユーザーに /dev/i2c-* への権限を与えます。

ddcutil detect --brief
ネットワーク：各ホストでUDP 24801 のIPv4ブロードキャストを許可してください。Wi-Fiのクライアント分離が有効だとノードを発見できません。

初回設定と運用

各ホストで一度、端末から対話起動します。サーバー、証明書、ペアリングコードはありません。

1

ホスト番号

Logitech機器のホスト選択キーに印字された、このPCの番号を指定します。ノード間で重複させません。

2

リーダーとフォロワー

切り替えを始動するキーボードをリーダーに、追従する機器をフォロワーにします。Bluetooth機器が見えなければ、このPCへ接続して「Refresh devices」を選びます。

3

モニターとクリップボード

モニターごとに、このPCにつながるFeature 0x60 の入力値を選び、クリップボード同期の要否を決めて保存します。

4

全ホストで起動

logitech-flow-kvm flow-node --secret '全ホストで同じ値'

設定は ~/.config/Logitech Flow KVM/node.json に保存されます。共有シークレットは保存されず、起動ごとに必要です。

「not currently detected」は正常です：Bluetooth機器が別ホストにつながっている間も保存済み機器として表示されます。現在その機器に到達できるノードだけが切り替えます。

要件とセキュリティ

項目内容
通信同一LAN上のUDP 24801 / IPv4ブロードキャスト。共有シークレットで認証・暗号化し、リプレイを防止します。
シークレット設定には保存されません。コマンドライン指定のため、シェル履歴とプロセス一覧に現れ得ます。
クリップボードGUIセッションへのアクセスが必要。サービス起動時はX11/WaylandとセッションDBusの環境・権限を引き継ぎます。
ログ~/.local/state/Logitech Flow KVM/log/logitech-flow-kvm.log。5MBでローテーションし、バックアップは5個です。

トラブルシューティング

ほかのノードが見つからない

全ノードを同じシークレットで起動し、UDP 24801、ファイアウォール、Wi-Fiクライアント分離を確認します。

機器の検出でPermission deniedになる

udevルールを再導入・再読み込みし、機器を再接続するか再起動します。SSH専用サービスでは専用グループと MODE="0660" のローカルルールを検討します。

モニター入力を選べない／切り替わらない

DDC/CIを有効にして ddcutil detect --brief を確認。EACCESならI²C権限を付与して再ログインします。Feature 0x60を公開しないモニターは自動設定できません。

クリップボードだけ同期しない

GUIセッション内から起動します。サービスやSSHではX11/WaylandとDBusの環境・権限を引き継ぎます。

詳しい状態を確認したい

TUIとログを確認します。機器一覧は logitech-flow-kvm list-devices、接続イベントは logitech-flow-kvm watch PATH で確認できます。

PeerKVM for Logitech · Unofficial · Peer to peer

One key. Everything follows.

Move your mouse, clipboard, and monitor input to the same Linux host with one keyboard key. An encrypted Flow-style KVM with no central server.

Unofficial derivative project: Not affiliated with, endorsed by, or supported by Logitech. Derived from Adam Coddington’s original logitech-flow-kvm, with its MIT-licensed history and attribution preserved.

What it does

Run the same flow-node on every PC. Authenticated LAN broadcasts tell peers where the leader arrived; the peer that still holds a follower moves it.

01 / DEVICES

Devices follow

Use a keyboard as leader and mice as followers. Supports Unifying/Bolt receivers and Bluetooth.

02 / CLIPBOARD

Clipboard follows

Synchronize clipboard contents during a switch, with a per-node opt-out.

03 / DISPLAY

Displays follow

Use ddcutil and DDC/CI to select the destination input.

How switching works

1Keyboard leaves host 1
2Host 2 detects it
3Host 2 broadcasts securely
4Host 1 moves the mouse
5Display and clipboard follow

Install

Repeat on every Linux host. Requires Python 3.10+, one LAN allowing IPv4 broadcast, and the same shared secret.

1

Run from the repository

git clone https://github.com/coddingtonbear/logitech-flow-kvm.git
cd logitech-flow-kvm
uv run --frozen logitech-flow-kvm flow-node --secret 'a-long-random-shared-value'
2

Bluetooth permissions

sudo install -m 0644 rules.d/42-logitech-flow-kvm.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules

Reconnect the device afterward.

3

Monitor switching (optional)

Install ddcutil, enable DDC/CI, and grant access to /dev/i2c-*.

ddcutil detect --brief
Network: allow IPv4 broadcasts on UDP 24801. Wi-Fi client isolation prevents discovery.

First-time setup

1

Choose this host number

Use the Logitech host-key number assigned to this PC. It must be unique.

2

Choose leader and followers

Select the keyboard that initiates switching and all followers. Connect a missing Bluetooth device here and choose “Refresh devices.”

3

Choose display inputs and clipboard

Select each monitor's Feature 0x60 input wired to this PC, then save.

4

Start every peer

logitech-flow-kvm flow-node --secret 'the-same-value-on-every-peer'

Config: ~/.config/Logitech Flow KVM/node.json. The secret is never saved.

“Not currently detected” is normal: a Bluetooth device remains listed while attached elsewhere. Only the peer that can reach it attempts a switch.

Requirements and security

AreaDetails
TransportUDP 24801 IPv4 broadcast. Packets are authenticated, encrypted, and replay-protected.
SecretNot stored in config; it may appear in shell history and process listings.
ClipboardRequires GUI-session access. Services need the applicable X11/Wayland and D-Bus environment and permissions.
Logs~/.local/state/Logitech Flow KVM/log/logitech-flow-kvm.log, 5 MB with five backups.

Troubleshooting

No peers discovered

Use the same secret everywhere; check UDP 24801, firewalls, and Wi-Fi client isolation.

Device discovery says permission denied

Reload the udev rule, reconnect, or reboot. Headless services may need a dedicated group and MODE="0660".

Monitor does not switch

Enable DDC/CI, run ddcutil detect --brief, and fix I²C permissions on EACCES.

Only clipboard sync fails

Run in the GUI session or propagate the relevant X11/Wayland and session D-Bus environment.

Need more detail

Read the TUI and log. Use list-devices and watch PATH for device diagnostics.

主要功能

每台电脑运行相同的 flow-node。主设备到达节点后，该节点通过认证广播通知其他节点；持有从设备的节点会将其切换过去。

01 / DEVICES

设备跟随

键盘作为主设备，鼠标等作为从设备。支持 Unifying/Bolt 和蓝牙。

02 / CLIPBOARD

剪贴板跟随

切换时同步剪贴板，也可按节点禁用。

03 / DISPLAY

显示器跟随

通过 ddcutil 和 DDC/CI 自动选择目标输入源。

切换过程

1键盘离开主机 1
2主机 2 检测连接
3主机 2 安全广播
4主机 1 切换鼠标
5显示器与剪贴板跟随

安装

在每台 Linux 主机执行。需要 Python 3.10+、允许 IPv4 广播的同一局域网及相同共享密钥。

1

从仓库运行

git clone https://github.com/coddingtonbear/logitech-flow-kvm.git
cd logitech-flow-kvm
uv run --frozen logitech-flow-kvm flow-node --secret '足够长的随机共享值'
2

蓝牙权限

sudo install -m 0644 rules.d/42-logitech-flow-kvm.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules

之后重新连接设备。

3

显示器切换（可选）

安装 ddcutil，启用 DDC/CI，并授予 /dev/i2c-* 权限。

ddcutil detect --brief
网络：允许 UDP 24801 IPv4 广播。Wi-Fi 客户端隔离会阻止发现。

首次设置

1

设置本机编号

选择分配给本机的 Logitech 主机键编号，各节点不可重复。

2

选择主设备与从设备

选择发起切换的键盘和跟随设备。蓝牙设备未显示时，连接到本机并选择“Refresh devices”。

3

选择显示器与剪贴板

选择连接本机的 Feature 0x60 输入值，然后保存。

4

启动所有节点

logitech-flow-kvm flow-node --secret '所有节点使用同一值'

配置：~/.config/Logitech Flow KVM/node.json。密钥不会保存。

“Not currently detected” 是正常状态：蓝牙设备连接其他主机时仍保留在列表中。只有能访问它的节点才会切换。

要求与安全

项目说明
通信UDP 24801 IPv4 广播；数据包经过认证、加密并防止重放。
密钥不写入配置，但可能出现在 Shell 历史和进程列表。
剪贴板需要图形会话权限；服务须继承 X11/Wayland 和会话 D-Bus 环境。
日志~/.local/state/Logitech Flow KVM/log/logitech-flow-kvm.log，5 MB，保留5个备份。

故障排除

找不到其他节点

确认共享密钥相同，并检查 UDP 24801、防火墙及 Wi-Fi 客户端隔离。

设备发现提示 Permission denied

重新加载 udev 规则并重连或重启。无界面服务可能需要专用组及 MODE="0660"。

显示器无法切换

启用 DDC/CI，运行 ddcutil detect --brief，出现 EACCES 时修复 I²C 权限。

只有剪贴板无法同步

在图形会话中运行，或传递 X11/Wayland 和会话 D-Bus 环境与权限。

需要更多信息

查看 TUI 和日志，用 list-devices 与 watch PATH 诊断设备。
